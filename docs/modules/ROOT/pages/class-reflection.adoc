= Reflect classes and fields

JRM reflects explicitly marked classes and structs.
It generates identity metadata, metadata for direct fields, field lookup, and serialization helpers.

== Declare a reflected type

[source,cpp]
----
include::example$quickstart/model.h[tag=reflected_classes]
----

The important rules are:

* place `CLASS()` immediately before the definition, not a forward declaration;
* place `R_FRIEND(Type)` inside the class, using the unqualified class name;
* list serializable reflected bases after the class name in `R_FRIEND(Derived, Base1, Base2)`;
* place `FIELD()` immediately before each field that belongs to the reflection surface;
* include the generated companion after all declarations in the header.

Public, protected, and private fields can be reflected because the generated `R<T>` specialization is a friend.
Methods and unmarked members are not part of class field metadata.
Treat unusual data declarators such as bit-fields and marked static members as unsupported unless a focused generator test proves the exact form.

== Inspect metadata

[source,cpp]
----
include::example$quickstart/main.cpp[tag=class_metadata]
----

`GetFields()` returns `RClassField` entries containing a textual type, field name, and zero or more marker attributes.
`GetFieldsMap()` indexes equivalent metadata by field name.
Metadata describes fields declared directly in the type; base fields are serialized through the base specialization but are not added to the derived type's `GetFields()` result.

== Access a field by name

[source,cpp]
----
include::example$quickstart/main.cpp[tag=dynamic_field_access]
----

`GetField` calls the callback synchronously with an untyped address and textual type, and returns `false` for an unknown name or empty callback.
The caller is responsible for checking the type string before casting.
Because the API exposes mutable addresses and currently casts away constness for a reflected const field, reserve it for controlled infrastructure such as editors or serializers.

== Defaults, requirements, and attributes

A field initializer becomes the generated deserialization fallback unless `R::NoDefaultValue` is present.
Without a usable initializer, JRM value-initializes the field type as the fallback.

`R::Required` makes a missing JSON key an error; `R::NonRequired` is the default.
`R::Attr = Identifier` records the identifier as metadata without changing serialization behavior.
Multiple attributes are preserved in declaration order.

See xref:markers.adoc[Marker macros and field options] for the complete option table.
