Getting started

This guide builds JRM, connects its runtime adapter and generator to an application, and reflects a small inheritance model.

Prerequisites

The current CMake project requires:

  • CMake 3.30 or newer;

  • a GCC, Clang, or MSVC toolchain with the CMake cxx_std_23 feature;

  • Git submodules for the bundled dependencies;

  • a build system supported by CMake, with Ninja used in the examples.

Project policy targets C26 as toolchains mature, but the shipped build currently requests C23.

Build JRM itself

git clone --recurse-submodules https://github.com/ValeriiKoniushenko/JustReflectMe.git
cd JustReflectMe
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DJRM_DISABLE_TESTS=OFF
cmake --build build --parallel

The resulting generator is build/bin/jrm; with tests enabled, the test executable is build/bin/JRMTests.

Integrate it into a CMake application

Add the checkout as a subdirectory and link the runtime adapter:

set(JRM_DISABLE_TESTS ON)
add_subdirectory("${JRM_SOURCE_DIR}" jrm-build)

add_executable(jrm_quickstart main.cpp)
target_link_libraries(jrm_quickstart PRIVATE JustReflectMe::Adapter)

Then create a generator target and make the application depend on it:

add_custom_target(jrm_quickstart_codegen ALL
    COMMAND $<TARGET_FILE:jrm> "${CMAKE_CURRENT_SOURCE_DIR}"
    DEPENDS jrm
    WORKING_DIRECTORY "${CMAKE_CURRENT_SOURCE_DIR}"
    VERBATIM
)
add_dependencies(jrm_quickstart jrm_quickstart_codegen)

Use $<TARGET_FILE:jrm> rather than assuming the executable path; this works across single- and multi-configuration CMake generators. The generator must run before compilation because the reflected header includes its generated companion.

The checked-in example’s JRM_SOURCE_DIR points back to this repository. In another project, set it to the location where JRM was cloned or vendored. If that directory sits below the scanned project root, add its relative path to excludedPaths.

Declare reflected types

Include the adapter, put ENUM_CLASS() before a scoped enum, and put CLASS() before a class or struct. Every reflected class needs R_FRIEND; only fields immediately marked with FIELD() are included.

ENUM_CLASS();
enum class Priority
{
    Low,
    Normal,
    High
};
CLASS();
class Entity
{
    R_FRIEND(Entity);

public:
    FIELD(R::Required, R::Attr = Identity);
    int id = 0;
};

CLASS();
class Task : public Entity
{
    R_FRIEND(Task, Entity);

public:
    FIELD();
    std::string title = "Untitled";

    FIELD();
    Priority priority = Priority::Normal;
};

On the first scan, JRM appends the generated-header include to the source header:

#include "model.generated.h" // Added automatically by jrm after the first scan.

Do not edit model.generated.h; a later scan replaces it.

Run the generator

The CMake target runs automatically in this example, or you can scan a project directly:

build/bin/jrm /absolute/path/to/your/project

The project path must exist. The first run creates .jrm/config.yaml and .jrm/cache.data in that project root.

Consume the metadata

    std::cout << R<Priority>::FullName() << " has " << R<Priority>::Size() << " values\n";
    std::cout << R<Priority>::ToString(Priority::High) << '\n';

    if (const auto value = R<Priority>::FromString("Normal"))
    {
        std::cout << static_cast<int>(*value) << '\n';
    }
    std::cout << R<Task>::FullName() << '\n';
    for (const RClassField& field : R<Task>::GetFields())
    {
        std::cout << field.type << ' ' << field.name << '\n';
    }
